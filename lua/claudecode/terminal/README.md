# claudecode.terminal providers

## Overview

This directory holds the terminal providers that host the Claude Code CLI inside or outside Neovim. The dispatcher module `claudecode.terminal` ([`../terminal.lua`](../terminal.lua)) selects one provider, then forwards calls to it with a prepared command string, an env table, and an effective config. This directory also holds `paste_fix.lua`, a shim for a Neovim streamed-paste bug.

| Provider       | How Claude runs                                                |
| -------------- | -------------------------------------------------------------- |
| `native.lua`   | `vim.fn.termopen` in a split that the plugin manages           |
| `snacks.lua`   | `Snacks.terminal.open` from snacks.nvim                        |
| `external.lua` | `vim.fn.jobstart` with `detach = true`, running a user command |
| `none.lua`     | No-op. The user runs Claude Code themselves                    |

## Interface

### Provider contract

The dispatcher requires these 7 callable fields on a custom table provider [terminal.lua:validate_and_enhance_provider]:

- `setup(config)` [terminal/native.lua:M.setup]. `snacks.setup()` ignores its argument [terminal/snacks.lua:M.setup]. `none.setup` is a no-op [terminal/none.lua:M.setup]
- `open(cmd_string, env_table, effective_config, focus)` [terminal/native.lua:M.open]. `external.open(cmd_string, env_table)` ignores config and focus [terminal/external.lua:M.open]
- `close()` [terminal/native.lua:M.close]
- `simple_toggle(cmd_string, env_table, effective_config)` [terminal/native.lua:M.simple_toggle]
- `focus_toggle(cmd_string, env_table, effective_config)` [terminal/native.lua:M.focus_toggle]
- `get_active_bufnr() -> bufnr|nil`. `external` and `none` always return `nil` [terminal/external.lua:M.get_active_bufnr]
- `is_available() -> boolean`. `native`, `external`, and `none` always return `true` [terminal/native.lua:M.is_available] [terminal/external.lua:M.is_available] [terminal/none.lua:M.is_available]. `snacks` tries to load snacks.nvim once, when the module loads. It checks `Snacks.terminal` again on every call [terminal/snacks.lua:M.is_available] [terminal/snacks.lua:is_available]

Optional fields (the dispatcher does not require them):

- `toggle(...)`: a legacy alias of `simple_toggle`. All four providers define it. `validate_and_enhance_provider` adds a default that calls `simple_toggle` when it is missing, but only for a custom table provider [terminal/native.lua:M.toggle] [terminal.lua:validate_and_enhance_provider]
- `validate_and_enhance_provider` changes the custom table in place. A field counts as callable when it is a function or a table with `__call`. It returns `nil` and a message such as "Custom provider missing required function: X" for a bad table [terminal.lua:validate_and_enhance_provider]
- `ensure_visible()`: defined as a no-op only in `external` and `none`. The dispatcher calls it only when present [terminal/external.lua:M.ensure_visible]
- `_get_terminal_for_test()`: defined in `snacks`, `external`, and `none`. `native` does not define it. `validate_and_enhance_provider` adds a default that returns `nil`, but only for a custom table provider. For a built-in provider, `M._get_managed_terminal_for_test` checks that the field exists and returns `nil` when it is missing [terminal/snacks.lua:M._get_terminal_for_test] [terminal.lua:M._get_managed_terminal_for_test]
- The provider type is declared as `ClaudeCodeTerminalProvider`. It declares `toggle` and `_get_terminal_for_test` as required (no `?`), so the type and the dispatcher disagree [types.lua:ClaudeCodeTerminalProvider]

### `paste_fix.lua`

- `is_affected_version() -> boolean`: true for Neovim before 0.12.2, including a 0.12.2 prerelease [terminal/paste_fix.lua:M.is_affected_version]
- `should_enable(opt) -> boolean`: `true` and `false` map to themselves. Any other value (`"auto"`, `nil`, or another string) uses `is_affected_version()` [terminal/paste_fix.lua:M.should_enable]
- `install()`: installs the `vim.paste` wrapper once (idempotent) [terminal/paste_fix.lua:M.install]
- `apply(opt)`: sets the enabled flag and installs when enabled. It never uninstalls, so `apply(false)` after an install leaves the wrapper in place as a pass-through [terminal/paste_fix.lua:M.apply]
- `_accumulate(acc, lines)`: appends one streamed chunk to `acc` in place and joins `lines[1]` onto the last element, the mid-line seam. The installed wrapper calls it for each buffered phase [terminal/paste_fix.lua:M._accumulate] [terminal/paste_fix.lua:M.install]
- Test helpers: `_is_installed()` and `_is_enabled()` [terminal/paste_fix.lua:M._is_installed]

## Invariants

- `external` tracks one job. It counts as running only when `jobid > 0`. `open` does nothing while a job is running [terminal/external.lua:is_valid]
- `external.open` refuses (ERROR notify) when `provider_opts.external_terminal_cmd` is unset. A string command must not be empty and must contain 1 or 2 `%s` placeholders. A function command must return a string or a table [terminal/external.lua:M.open]
- `external.open` runs the job in `vim.fn.getcwd()`. It calls `jobstart` through `pcall`. When `jobstart` raises (for example `E475` for a command that is not executable) or returns `0` or `-1`, it sends one ERROR notification, which includes the error text when `jobstart` raised, and clears `jobid` [terminal/external.lua:M.open]
- `external` reads `external_terminal_cmd` from the config that `setup` stored, not from the effective config. A string with 1 `%s` gets the command. A string with 2 gets the cwd, then the command. `external` formats it with `string.format` outside `pcall`, so another `%` sequence such as `%d` raises a Lua error instead of sending an ERROR notification. It splits a string with `utils.parse_command`. A function gets `(cmd_string, env_table)`, and a table it returns is used as the argv list [terminal/external.lua:M.open]
- `external`'s `on_exit` clears the state, scheduled, only when the job that exited is still the tracked one. `simple_toggle`, `focus_toggle`, and `toggle` stop a running job instead of hiding it [terminal/external.lua:M.open] [terminal/external.lua:M.simple_toggle]
- `native` clears `bufnr`, `winid`, and `jobid` when its buffer is invalid. When the tracked window is gone or shows another buffer (for example after `:e file` in it), it recovers `winid` by scanning windows that show the buffer, and it clears `winid` when none does, so the terminal counts as hidden [terminal/native.lua:is_valid]
- `native` passes an argv list from `utils.parse_command` to `termopen`, so no shell runs. It opens the split with `topleft` when `split_side` is `"left"`, else `botright`, `floor(columns * split_width_percentage)` columns wide and the full editor height. A hidden terminal comes back in the same kind of split [terminal/native.lua:open_terminal] [terminal/native.lua:show_hidden_terminal]
- `native` uses the effective config of each call for `auto_insert` and `auto_close` of a terminal it starts. It uses the config from `setup` for `focus_terminal`'s `auto_insert`, for the `auto_close` of an adopted terminal, and for `show_native_term_exit_tip` [terminal/native.lua:focus_terminal] [terminal/native.lua:adopt_existing_terminal]
- `native`'s `simple_toggle` and `focus_toggle` show a hidden terminal focused. `focus_toggle` hides the terminal only when the cursor is in its window, and focuses it when it is visible elsewhere [terminal/native.lua:M.simple_toggle] [terminal/native.lua:M.focus_toggle]
- `native` sets `bufhidden=hide`, so the Claude job survives when its window closes [terminal/native.lua:open_terminal]. Hide closes the window without force, and the buffer stays alive. When the window is the last window, hide does nothing, because Neovim raises `E444` for it [terminal/native.lua:hide_terminal]
- `native` sets `filetype=claudecode` on the terminal buffer once, after `termopen` started the job, so a `FileType claudecode` autocmd runs once per terminal with `buftype=terminal`. A failed start sets none, and a hide or show of the same buffer sets none again [terminal/native.lua:open_terminal]
- `native` calls `termopen` through `pcall`. Neovim raises `E475` for a command that is not executable. When `:silent!` is in effect, `termopen` returns `-1` instead, also inside `pcall`. A plain `:silent` or `pcall` alone does not silence the error. `termopen` returns `0` only for invalid arguments, such as an empty argv (`E474`), and only under `:silent!`. When an autocmd deletes the new buffer before `termopen` runs, `native` skips `termopen` and treats it as a failure. When a `TermOpen` autocmd wipes the buffer after `termopen` started the job, the wipe also stops the job, and `native` treats it as a failure. On any of these failures `native` sends one ERROR notification, which includes the error text when `termopen` raised. Its callers (`M.open`, `M.simple_toggle`, and `M.focus_toggle`) send none. `native` also closes the new window, restores the original window, deletes the buffer it created, and clears its state. A buffer that an autocmd swapped into the split stays [terminal/native.lua:open_terminal]
- `native` shows the exit tip once per load of the module when `show_native_term_exit_tip` is set. The flag that limits it is module-local, so a reload of the module resets it [terminal/native.lua:open_terminal]
- `native` marks each terminal buffer it starts with `b:claudecode_native_terminal`, before `termopen` runs. It clears the mark when the job exits [terminal/native.lua:open_terminal]. While it tracks no terminal, `open`, `simple_toggle`, and `focus_toggle` adopt a marked buffer that a window displays and whose job has not ended, and take its job id from the buffer's `'channel'` option. A buffer whose job has not started yet counts as not ended. They never adopt an unmarked terminal, even when its name contains `claude`. Before they look at the tracked terminal, they run the exit handling of a terminal whose job already ended but whose scheduled exit handling has not run yet, so they start a new Claude instead of showing the dead one. That handling uses the `auto_close` of the config that started (or adopted) the job. `get_active_bufnr` returns `nil` for such a terminal [terminal/native.lua:forget_ended_terminal]. The job's `on_exit` belongs to the module copy that started it, for example the one before a reload, so adoption adds a buffer-local `TermClose` handler that runs the same exit handling. The handler sits in the `ClaudeCodeNativeAdopted` augroup, and each adoption replaces the buffer's earlier one, so a buffer keeps one handler however many reloads adopt it [terminal/native.lua:adopt_existing_terminal]. `close` and `get_active_bufnr` never adopt, so after a reload `close` does nothing and `get_active_bufnr` returns `nil` until an `open` or a toggle adopts the terminal [terminal/native.lua:M.close] [terminal/native.lua:M.get_active_bufnr]
- `snacks.is_available` requires snacks.nvim to load and `Snacks.terminal` to exist. It tries to load snacks.nvim once, when the module loads. It checks `Snacks.terminal` again on every call. Without Snacks, `open`, `simple_toggle`, and `focus_toggle` send an ERROR notification, and `close` returns without one [terminal/snacks.lua:is_available] [terminal/snacks.lua:M.open] [terminal/snacks.lua:M.close]
- `snacks.focus_toggle` shows and focuses a hidden terminal, hides a focused one, and focuses a visible one that does not have the cursor. A terminal is visible only when its window is valid, not hidden through its config, and shows the terminal buffer [terminal/snacks.lua:M.focus_toggle] [terminal/snacks.lua:cc_is_visible]
- `snacks` reuses the tracked instance while `terminal:buf_valid()` is true. It passes an argv list from `utils.parse_command`, so no shell expands bracketed model aliases [terminal/snacks.lua:M.open]
- `snacks` calls `Snacks.terminal.open` through `pcall`. Snacks shows its window before it calls `termopen`, so `snacks` wraps `on_buf` to capture the instance and then calls any `on_buf` from `snacks_win_opts`. `snacks` sets its state only after `Snacks.terminal.open` returns, and a `starting` flag marks that call. So an `open` that an autocmd (for example `BufEnter` or `TermOpen`) calls during it does nothing, and one Claude runs [terminal/snacks.lua:M.open]. A start fails when `termopen` raises (for example `E475` for a command that is not executable) or when the buffer is not a terminal afterwards (`termopen` returns `-1` when `:silent!` is in effect). On a failed start `snacks` closes the Snacks window, deletes its scratch buffer, clears its state, and sends one ERROR notification with the first line of the error. The notification shows the command but not the env table. The DEBUG log of the failed start lists the env keys but not their values [terminal/snacks.lua:M.open]
- `snacks` forces `auto_close = false` on the Snacks instance. It sets `start_insert` and `auto_insert` only when focusing and `auto_insert ~= false` [terminal/snacks.lua:build_opts]
- `snacks` gives the Snacks window the default `bo = { filetype = "claudecode" }`. It replaces the `snacks_terminal` filetype of the Snacks terminal style, so a `FileType snacks_terminal` autocmd no longer matches the Claude buffer. `snacks_win_opts` is deep-merged over the default, so `snacks_win_opts.bo.filetype` wins, `"snacks_terminal"` restores the Snacks filetype, and other `bo` keys keep the default filetype. The default also wins over a `bo.filetype` in the user's global snacks.nvim config (`styles.terminal`, `terminal.win`) or in a style named by `snacks_win_opts`, because Snacks ranks the options passed to `Snacks.terminal.open` above them. Snacks applies `bo` when it creates the buffer, before `termopen` (`buftype` is still `nofile`) and before it opens the window, so a window option set in a `FileType` handler does not reach the Claude window when it opens. Snacks applies `bo` again on a `VimResized` event, because snacks.nvim's `Win:on_resize` calls `Win:update`. With the Claude window open, a resize of the editor runs `FileType claudecode` again, and a window option set in that handler then reaches the Claude window. Snacks also applies `bo` again when it re-creates a window itself. `snacks` lets it do that when `snacks_win_opts.position` is not `left`, `right`, `top`, or `bottom` (for example `float`), and for a float that `snacks` hid whose window is gone. On Neovim before 0.10, hiding a float closes its window. A split is re-created with `split` (top or bottom) or `vsplit` (left or right), so `FileType` does not fire again for it [terminal/snacks.lua:build_opts] [terminal/snacks.lua:cc_show] [terminal/snacks.lua:cc_hide]
- `external` and `none` create no Neovim buffer, so they set no filetype [terminal/external.lua:M.open] [terminal/none.lua:M.open]
- `snacks` overrides the instance's `hide`, `show`, and `toggle` methods and keeps the originals in `term._cc`. The patched `show` and `toggle` always focus and use the config captured at open [terminal/snacks.lua:patch_instance]
- `snacks` hides floats with `nvim_win_set_config({hide=true})` only on Neovim 0.10 and later. It also hides the Snacks backdrop window, and show un-hides both. When the cursor is in the float it hides, it runs `wincmd p` to leave it. It closes split windows and re-creates them on show. It closes a split through `pcall`, so hiding the last window does nothing [terminal/snacks.lua:cc_hide] [terminal/snacks.lua:set_backdrop_hidden]
- A top or bottom split that `snacks` re-creates takes its height from `snacks_win_opts.height`, else 30% of the editor lines. A left or right split takes its width from `snacks_win_opts.width`, else `split_width_percentage` of the editor columns, and gets the full editor height [terminal/snacks.lua:cc_show] [terminal/snacks.lua:resolve_split_size]
- `paste_fix` decides at phase 1 whether a streamed paste targets the managed terminal. It replays the whole paste once as phase -1, inside the captured window if focus moved. When that window is no longer valid, it replays in the current window [terminal/paste_fix.lua:M.install]
- `paste_fix` passes other pastes, and all pastes while disabled, to the original `vim.paste` unchanged. `is_managed_terminal` reads `vim.bo[bufnr].buftype` outside `pcall`, so it throws for an invalid `bufnr`. Its only caller passes the current buffer [terminal/paste_fix.lua:is_managed_terminal]

## Side Effects

- `native` runs `vsplit`, shows a new listed buffer from `nvim_create_buf` in the split, then runs `vim.fn.termopen` in that buffer with the command, env, and cwd. This spawns the Claude process. When an autocmd swapped another buffer into the split, `native` shows its terminal buffer there after the start. It runs `startinsert` when focused and `auto_insert` is not `false` [terminal/native.lua:open_terminal]
- `native` on exit clears its state, for its own terminal and for an adopted one. With `auto_close` it closes the tracked window only if the window still shows the terminal buffer. When the buffer is gone (wiped), it closes no window. It never closes the last window (the only non-floating window of the only tab page), which keeps showing the exited terminal [terminal/native.lua:forget_exited_job]
- `native.close` clears its state and the buffer's mark, so an `open` that runs during the wait starts a new terminal. It registers a one-shot, buffer-local `TermClose` autocmd that detects the exit. It calls `jobstop`, and when `jobstop` reports a running job, it waits up to 1 s for the job to exit. A close from a `TermClose` autocmd does not wait, because the job already exited. It then force-deletes the terminal buffer. Neovim closes the other windows that show it, and the editor's last window stays and shows another buffer. This works for a visible, hidden, or adopted terminal. Deleting the buffer before the job exits can hang Neovim when text sent to the job is still pending (neovim/neovim#42508). The wait does not prevent that hang for a job that stopped reading, for example `yes`, or `cat` after a large multi-line paste [terminal/native.lua:close_terminal]
- `snacks` calls `Snacks.terminal.open`, which spawns the Claude process [terminal/snacks.lua:M.open]
- `snacks` always registers a buffer-local `BufWipeout` handler. It registers a buffer-local `TermClose` handler only when `auto_close` is true. `TermClose` logs an ERROR on a nonzero exit, except when `close` stopped the job, then schedules `close({ buf = true })` on the instance and `checktime`. Both handlers stop tracking the instance only while it is still the tracked one [terminal/snacks.lua:setup_terminal_events]
- `snacks.close` stops tracking the instance first, so an `open` that runs during the wait starts a new terminal. For a running job, it registers a one-shot, buffer-local `TermClose` autocmd that detects the exit. It stops the job and waits up to 1 s for it to exit. It then closes the Snacks window, which wipes the terminal buffer. Deleting the buffer before the job exits can hang Neovim when text sent to the job is still pending (neovim/neovim#42508). The wait does not prevent that hang for a job that stopped reading, for example `yes`, or `cat` after a large multi-line paste. An exited job is not waited for. Hide keeps the job running [terminal/snacks.lua:M.close]
- `snacks` maps terminal-mode `<S-CR>` to send a backslash and then a carriage return after 10 ms [terminal/snacks.lua:build_opts]
- `snacks` sets window options and `vim.w[win].snacks_win` on re-created splits [terminal/snacks.lua:reapply_snacks_window_state]
- `external` spawns a detached process with `vim.fn.jobstart`. `close` calls `vim.fn.jobstop` [terminal/external.lua:M.close]
- `none` has no side effects [terminal/none.lua:M.open]
- `paste_fix.install` replaces the global `vim.paste` once. The dispatcher calls the provider's `setup(defaults)`, then `paste_fix.apply(defaults.fix_streamed_paste)`. The default is `"auto"`, and a value other than a boolean or `"auto"` gets a WARN and keeps the previous value [terminal.lua:M.setup]
