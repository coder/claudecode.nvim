# claudecode.terminal providers

## Overview

This directory holds the terminal providers that host the Claude Code CLI inside or outside Neovim. The dispatcher module `claudecode.terminal` ([`../terminal.lua`](../terminal.lua)) selects one provider, then forwards calls to it with a prepared command string, an env table, and an effective config. This directory also holds `paste_fix.lua`, a shim for a Neovim streamed-paste bug.

| Provider       | How Claude runs                                                |
| -------------- | -------------------------------------------------------------- |
| `native.lua`   | `vim.fn.termopen` in a split that the plugin manages           |
| `snacks.lua`   | `Snacks.terminal.open` from snacks.nvim                        |
| `external.lua` | `vim.fn.jobstart` with `detach = true`, running a user command |
| `none.lua`     | No-op. The user runs Claude Code themselves                    |

`owned.lua` is not a provider. It finds the Claude terminal buffers that `native` and `snacks` started, also after a plugin reload (see below).

## Interface

### Provider contract

The dispatcher requires these 7 callable fields on a custom table provider [terminal.lua:validate_and_enhance_provider]:

- `setup(config)` [terminal/native.lua:M.setup]. `snacks.setup()` ignores its argument [terminal/snacks.lua:M.setup]. `none.setup` is a no-op [terminal/none.lua:M.setup]
- `open(cmd_string, env_table, effective_config, focus)` [terminal/native.lua:M.open]. `external.open(cmd_string, env_table)` ignores config and focus [terminal/external.lua:M.open]
- `close()` [terminal/native.lua:M.close]
- `simple_toggle(cmd_string, env_table, effective_config)` [terminal/native.lua:M.simple_toggle]
- `focus_toggle(cmd_string, env_table, effective_config)` [terminal/native.lua:M.focus_toggle]
- `get_active_bufnr() -> bufnr|nil`. `external` and `none` always return `nil` [terminal/external.lua:M.get_active_bufnr]
- `is_available() -> boolean`. `native`, `external`, and `none` always return `true` [terminal/native.lua:M.is_available] [terminal/external.lua:M.is_available] [terminal/none.lua:M.is_available]. `snacks` tries to load snacks.nvim once, when the module loads. It checks `Snacks.terminal` again on every call [terminal/snacks.lua:M.is_available] [terminal/snacks.lua:is_available]

Optional fields (the dispatcher does not require them):

- `toggle(...)`: a legacy alias of `simple_toggle`. All four providers define it. `validate_and_enhance_provider` adds a default that calls `simple_toggle` when it is missing, but only for a custom table provider [terminal/native.lua:M.toggle] [terminal.lua:validate_and_enhance_provider]
- `validate_and_enhance_provider` changes the custom table in place. A field counts as callable when it is a function or a table with `__call`. It returns `nil` and a message such as "Custom provider missing required function: X" for a bad table [terminal.lua:validate_and_enhance_provider]
- `ensure_visible()`: defined as a no-op only in `external` and `none`. The dispatcher calls it only when present [terminal/external.lua:M.ensure_visible]
- `hide_float(tab?) -> boolean`: hides the terminal when it is a visible floating window, and with `tab` only when that window is in `tab`. It returns `true` when it did. A provider that ignores `tab` hides its float in any tab. `terminal.hide_float(tab)` passes `tab` on and returns `false` for a provider without it. Nothing shows the float again but the user's own terminal commands and the `ensure_visible` call: a diff in its own tab calls it when it closes, and every command that sends an @ mention (`:ClaudeCodeSend`, `:ClaudeCodeAdd`, `:ClaudeCodeTreeAdd`) calls it after a send to a connected Claude. Those commands call `open` instead with `focus_after_send`, or when Claude is not connected. Of the built-in providers, only `snacks` defines it. `diff.lua` calls it with the diff's tab when a window of the terminal in that tab is a float, unless `diff_opts.keep_terminal_focus` is set [terminal/snacks.lua:M.hide_float] [terminal.lua:M.hide_float]
- `_get_terminal_for_test()`: defined in `snacks`, `external`, and `none`. `native` does not define it. `validate_and_enhance_provider` adds a default that returns `nil`, but only for a custom table provider. For a built-in provider, `M._get_managed_terminal_for_test` checks that the field exists and returns `nil` when it is missing [terminal/snacks.lua:M._get_terminal_for_test] [terminal.lua:M._get_managed_terminal_for_test]
- The provider type is declared as `ClaudeCodeTerminalProvider`. It declares `toggle` and `_get_terminal_for_test` as required (no `?`), so the type and the dispatcher disagree [types.lua:ClaudeCodeTerminalProvider]
- A provider that creates a Neovim terminal buffer for Claude calls `utils.map_terminal_suspend(bufnr)` once for that buffer, so Ctrl-Z suspends Neovim and does not reach the Claude job. `native` and `snacks` do. `external` and `none` create no buffer and do not [utils.lua:M.map_terminal_suspend] [terminal/native.lua:open_terminal] [terminal/snacks.lua:M.open]

### `paste_fix.lua`

- `is_affected_version() -> boolean`: true for Neovim before 0.12.2, including a 0.12.2 prerelease [terminal/paste_fix.lua:M.is_affected_version]
- `should_enable(opt) -> boolean`: `true` and `false` map to themselves. Any other value (`"auto"`, `nil`, or another string) uses `is_affected_version()` [terminal/paste_fix.lua:M.should_enable]
- `install()`: installs the `vim.paste` wrapper once (idempotent) [terminal/paste_fix.lua:M.install]
- `apply(opt)`: sets the enabled flag and installs when enabled. It never uninstalls, so `apply(false)` after an install leaves the wrapper in place as a pass-through [terminal/paste_fix.lua:M.apply]
- `_accumulate(acc, lines)`: appends one streamed chunk to `acc` in place. When `acc` is not empty, it joins `lines[1]` onto the last element, the mid-line seam. An empty `lines` adds nothing. The installed wrapper calls it for each buffered phase [terminal/paste_fix.lua:M._accumulate] [terminal/paste_fix.lua:M.install]
- Test helpers: `_is_installed()` and `_is_enabled()` [terminal/paste_fix.lua:M._is_installed]

## Invariants

- `external` tracks one job. It counts as running only when `jobid > 0`. `open` does nothing while a job is running [terminal/external.lua:is_valid]
- `external.open` refuses (ERROR notify) when `provider_opts.external_terminal_cmd` is unset. A string command must not be empty and must contain 1 or 2 `%s` placeholders. A function command must return a string or a table [terminal/external.lua:M.open]
- `external.open` runs the job in `vim.fn.getcwd()`. It calls `jobstart` through `pcall`. When `jobstart` raises (for example `E475` for a command that is not executable) or returns `0` or `-1`, it sends one ERROR notification, which includes the error text when `jobstart` raised, and clears `jobid` [terminal/external.lua:M.open]
- `external` reads `external_terminal_cmd` from the config that `setup` stored, not from the effective config. A string with 1 `%s` gets the command. A string with 2 gets the cwd, then the command. `external` formats it with `string.format` outside `pcall`, so another `%` sequence such as `%d` raises a Lua error instead of sending an ERROR notification. It splits a string with `utils.parse_command`. A function gets `(cmd_string, env_table)`, and a table it returns is used as the argv list [terminal/external.lua:M.open]
- `external`'s `on_exit` clears the state, scheduled, only when the job that exited is still the tracked one. `simple_toggle`, `focus_toggle`, and `toggle` stop a running job instead of hiding it [terminal/external.lua:M.open] [terminal/external.lua:M.simple_toggle]
- `native` clears `bufnr`, `winid`, and `jobid` when its buffer is invalid. When the tracked window is gone or shows another buffer (for example after `:e file` in it), it recovers `winid` by scanning windows that show the buffer, and it clears `winid` when none does, so the terminal counts as hidden [terminal/native.lua:is_valid]
- `native` passes an argv list from `utils.parse_command` to `termopen`, so no shell runs. It opens the split with `topleft` when `split_side` is `"left"`, else `botright`, `floor(columns * split_width_percentage)` columns wide and the full editor height. A hidden terminal comes back in the same kind of split [terminal/native.lua:open_terminal] [terminal/native.lua:show_hidden_terminal]
- `native` uses the effective config of each call for `auto_insert` and `auto_close` of a terminal it starts. It uses the config from `setup` for `focus_terminal`'s `auto_insert`, for the `auto_close` of an adopted terminal, and for `show_native_term_exit_tip` [terminal/native.lua:focus_terminal] [terminal/native.lua:adopt_existing_terminal]
- `native`'s `simple_toggle` and `focus_toggle` show a hidden terminal focused. `focus_toggle` hides the terminal only when the cursor is in its window, and focuses it when it is visible elsewhere [terminal/native.lua:M.simple_toggle] [terminal/native.lua:M.focus_toggle]
- `native` sets `bufhidden=hide` on the new buffer before it shows it, and again after the autocmds of the start, so the Claude job survives when its window closes [terminal/native.lua:open_terminal]. A hide sets it again too, in case an autocmd of yours changed it since the start (to wipe, for example), and writes it only when it is not `hide`, because a write of the same value fires `OptionSet`. That event fires inside the write, and an autocmd of yours can end, hide or show Claude, or show a file in its window. So a hide looks at the window again after the write, and closes nothing when `winid` changed, its window is gone, it shows another buffer, or it became the last window [terminal/native.lua:hide_terminal]. Hide closes the window without force, and the buffer stays alive. When the window is the last window, hide does nothing, because Neovim raises `E444` for it [terminal/native.lua:hide_terminal]
- `native` sets `filetype=claudecode` on the terminal buffer once, after `termopen` started the job, so a `FileType claudecode` autocmd runs once per terminal with `buftype=terminal`. A failed start sets none, and a hide or show of the same buffer sets none again [terminal/native.lua:open_terminal]
- `native` calls `termopen` through `pcall`. Neovim raises `E475` for a command that is not executable. When `:silent!` is in effect, `termopen` returns `-1` instead, also inside `pcall`. A plain `:silent` or `pcall` alone does not silence the error. Under `:silent!`, `termopen` returns `0` instead for its other errors, such as an empty argv (`E474`), a `cwd` that is not a directory, or a modified buffer. When an autocmd deletes the new buffer before `termopen` runs, `native` skips `termopen` and treats it as a failure. When a `TermOpen` autocmd wipes the buffer after `termopen` started the job, the wipe also stops the job, and `native` treats it as a failure. On any of these failures `native` sends one ERROR notification, which includes the error text when `termopen` raised. Its callers (`M.open`, `M.simple_toggle`, and `M.focus_toggle`) send none. `native` also closes the new window, restores the original window, deletes the buffer it created, and clears its state. A buffer that an autocmd swapped into the split stays [terminal/native.lua:open_terminal]
- `native` shows the exit tip once per load of the module when `show_native_term_exit_tip` is set. The flag that limits it is module-local, so a reload of the module resets it [terminal/native.lua:open_terminal]
- `native` marks each terminal buffer it starts with `b:claudecode_native_terminal`, before `termopen` runs. It clears the mark when the job exits [terminal/native.lua:open_terminal]. While it tracks
  no terminal, `open`, `simple_toggle`, `focus_toggle`, `close`, and the first `get_active_bufnr` call of a module copy adopt a marked buffer whose job has not ended, whether or not a window displays
  it, and take its job id from the buffer's `'channel'` option [terminal/owned.lua:find]. `open`, `simple_toggle`, and `focus_toggle` show a hidden adopted terminal. A buffer whose job has not started
  yet counts as not ended. They never adopt an unmarked terminal, even when its name contains `claude`. Before they look at the tracked terminal, they run the exit handling of a terminal whose job
  already ended but whose scheduled exit handling has not run yet, so they start a new Claude instead of showing the dead one. That handling uses the `auto_close` of the config that started (or
  adopted) the job. `get_active_bufnr` returns `nil` for such a terminal [terminal/native.lua:forget_ended_terminal]. The job's `on_exit` belongs to the module copy that started it, for example the
  one before a reload, so adoption adds a buffer-local `TermClose` handler that runs the same exit handling. Before `native` starts a terminal, and when `close` finds none to adopt, it stops a live
  terminal that the `snacks` provider marked: the provider choice changed since the reload, and nothing else controls that Claude. The `snacks` provider closes it when its module loads and still finds
  it. Otherwise `owned.lua` waits for the child of the job to run `exec` (`owned.wait_for_exec`, for every job there because the start time is unknown, and over at the first look for a job that has run `exec`), stops the job, waits for `TermClose`, and deletes the buffer. A WARN notification follows once no such terminal runs, and an ERROR log when the buffer survives
  [terminal/owned.lua:stop_other] [terminal/native.lua:stop_snacks_terminal]. The handler sits in the `ClaudeCodeNativeAdopted` augroup, and each adoption replaces the buffer's earlier one, so a
  buffer keeps one handler however many reloads adopt it [terminal/native.lua:adopt_existing_terminal]
- `snacks.is_available` requires snacks.nvim to load and `Snacks.terminal` to exist. It tries to load snacks.nvim once, when the module loads. It checks `Snacks.terminal` again on every call. Without Snacks, `open`, `simple_toggle`, and `focus_toggle` send an ERROR notification, and `close` returns without one [terminal/snacks.lua:is_available] [terminal/snacks.lua:M.open] [terminal/snacks.lua:M.close]. The dispatcher checks `is_available` before each call and uses `native` instead, so only a direct call of the provider reaches these checks [terminal.lua:get_provider]
- `snacks.focus_toggle` shows and focuses a hidden terminal, hides a focused one, and focuses a visible one that does not have the cursor. A terminal is visible only when its window is valid, not hidden through its config, and shows the terminal buffer [terminal/snacks.lua:M.focus_toggle] [terminal/snacks.lua:cc_is_visible]
- `snacks` reuses the tracked instance while `terminal:buf_valid()` is true, except an instance whose Claude exited when `auto_close` is set: the entry forgets that one and starts a new Claude. It passes an argv list from `utils.parse_command`, so no shell expands bracketed model aliases [terminal/snacks.lua:M.open]
- `snacks` calls `Snacks.terminal.open` through `pcall`. Snacks shows its window before it calls `termopen`, so `snacks` wraps `on_buf` to capture the instance and then calls any `on_buf` from `snacks_win_opts`. `snacks` sets its state only after `Snacks.terminal.open` returns, so an `open` that an autocmd (for example `BufEnter` or `TermOpen`) calls during that call does nothing, and one Claude runs [terminal/snacks.lua:M.open] `snacks` marks the buffer of each terminal it starts with `b:claudecode_snacks_terminal`, and also writes `b:claudecode_snacks_auto_close` (whether it started with `auto_close`), `b:claudecode_snacks_window` (the resolved window options of its Snacks instance, as plain data without functions, `keys` and `bo`, and with the anchor `win` only for a float that is `relative = "win"`: the wrapper keeps it while that window exists, and Snacks would take the current window otherwise) and, for a float with a backdrop, `b:claudecode_snacks_backdrop` (the window id of that backdrop). Snacks makes a new backdrop each time it re-creates a float, so `snacks` writes the variable again after each re-creation, and clears it when the new float has no backdrop [terminal/snacks.lua:remember_backdrop]. While it tracks no terminal, `open`, `simple_toggle`, `focus_toggle`, `close`, and `get_active_bufnr` take a marked buffer whose job has not ended, whether or not a window shows it. They do not ask `Snacks.terminal.list()`: Snacks keys an instance by its command, directory, env and count, and clears that key when any buffer with that key is wiped, so a Claude that started while an exited one waited for its close would be missing from the list. They wrap the buffer in a new Snacks window (`Snacks.win` with `buf`, shown later, in the `terminal` style so that `q` hides the terminal and does not close it) with the options from the variable, and patch it like an instance that `snacks` started. A split or a float then comes back as it started, also when its window is gone. The wrapper maps its keys to the buffer (`Snacks.win:map`): the `terminal` style's `q` and `gf`, and the keys of the entry's config, functions included. The maps of the first start close over the instance that started the Claude, and once the wrapper has hidden and shown the terminal that instance has a stale window, so its `q` would do nothing and its `gf` would leave the file in Claude's window. An entry without a config (`close`, `get_active_bufnr`) maps no key, because a map without the user's keys would turn on a key that the user turned off (Snacks never removes a map), and a hide or a show needs the maps of the wrapper. The next entry that has a config maps them, and gives the wrapper the window options of a terminal that an older version started [terminal/snacks.lua:wrapper_options] [terminal/snacks.lua:upgrade_wrapper]. When it adopts, the wrapper takes a window that shows the buffer and that Snacks made for it, one that carries the `snacks_win` marker (a window that `nvim_win_set_buf` shows, such as the copy of a diff tab, does not): one of the current tab first, then one of another tab, and then an unmarked window of the current tab (a split that an older version re-created). An unmarked window of another tab counts for nothing. After that the wrapper tracks only the window that it hides and shows itself, as an instance that `snacks` started does, so a hide and a show never mistake a copy for the terminal's window [terminal/snacks.lua:find_window]. A wrapper starts without a `Win:show`, and `cc_show` re-creates a split without one (a float goes through `Win:show`, which registers its events), so the wrapper registers what `Win:show` registers: its events that do not belong to one window (the resizes), and the `BufWinEnter` handler that moves a file that you open in the terminal's window to another window. It does so once, at its first re-creation of a split. Without them an `:edit` in the window would replace Claude's buffer. It registers no `WinClosed` event, which is bound to the id of one window and which an instance that `snacks` started never has for a re-created window: Snacks' handler would move the cursor to the previous window when the window closes [terminal/snacks.lua:register_window_events]. Three things differ from an instance that `snacks` started itself: (1) a user's `on_win` and `on_buf` callbacks and any function in `snacks_win_opts` other than a key do not run for the wrapped window (a function cannot be stored in a buffer variable, and before the first entry with a config, the user's function keys are those of the first start); (2) the first start's `FileType` is not set again; (3) a terminal that an older version started has none of the variables, so the entry's config decides its window options (a split gets the default winbar) and its `auto_close`, and a float has no backdrop of its own to hide or to show (a float that was hidden before the upgrade comes back without its backdrop), until Snacks re-creates the float and `snacks` records the new backdrop [terminal/snacks.lua:adopted_config]. The wrapper is a new Snacks instance: the instance that the first start created stays alive for its `TermClose` and `BufWipeout` handlers on that buffer. Each of those calls first forgets a tracked terminal whose job ended, when it started with `auto_close`. So an `open` that runs between the exit and the scheduled close (for example from a `TermClose` autocmd that runs before the provider's handler, or after a reload, where the adopted terminal has only the earlier copy's handler) starts a new Claude instead of showing the dead terminal. Nothing is wiped there, because a wipe while Neovim dispatches `TermClose` would delete the buffer-local handlers that remain for that event [terminal/snacks.lua:forget_ended_terminal]. Before `snacks` starts a terminal, and when `close` finds none, it stops a live terminal that the `native` provider marked, the same way and with the same notification [terminal/owned.lua:stop_other] [terminal/snacks.lua:stop_native_terminal]. A start fails when `termopen` raises (for example `E475` for a command that is not executable) or when the buffer is not a terminal afterwards (`termopen` returns `-1` when errors are silenced). On a failed start `snacks` closes the Snacks window, deletes its scratch buffer, clears its state, and sends one ERROR notification with the first line of the error. The notification shows the command but not the env table. The DEBUG log of the failed start lists the env keys but not their values [terminal/snacks.lua:M.open]
- `snacks` forces `auto_close = false` on the Snacks instance. It sets `start_insert` only when focusing and `auto_insert ~= false`. It sets `auto_insert` whenever `auto_insert ~= false`, so a terminal created without focus also enters terminal mode on a later focus [terminal/snacks.lua:build_opts]
- `snacks` shows the terminal without focus (`focus = false`) with the caller's window and mode unchanged (#423). A new terminal gets `enter = false` for its creation, and a `snacks_win_opts.enter` still wins. The instance's `opts.enter` is set back to `snacks_win_opts.enter` after the start. A re-created split gets its buffer with `BufEnter` in `'eventignore'` (a `-BufEnter` entry is dropped for that call, and the old value is restored exactly), so the Snacks `auto_insert` autocmd cannot queue a `startinsert`. A float that Snacks re-creates is shown with `opts.enter = false` for that call, restored afterwards, unless `snacks_win_opts.enter` is set [terminal/snacks.lua:cc_show]
- `snacks` gives the Snacks window the default `bo = { filetype = "claudecode" }`. It replaces the `snacks_terminal` filetype of the Snacks terminal style, so a `FileType snacks_terminal` autocmd no longer matches the Claude buffer. `snacks_win_opts` is deep-merged over the default, so `snacks_win_opts.bo.filetype` wins, `"snacks_terminal"` restores the Snacks filetype, and other `bo` keys keep the default filetype. The default also wins over a `bo.filetype` in the user's global snacks.nvim config (`styles.terminal`, `terminal.win`) or in a style named by `snacks_win_opts`, because Snacks ranks the options passed to `Snacks.terminal.open` above them. Snacks applies `bo` when it creates the buffer, before `termopen` (`buftype` is still `nofile`) and before it opens the window, so a window option set in a `FileType` handler does not reach the Claude window when it opens. Snacks applies `bo` again on a `VimResized` event, because snacks.nvim's `Win:on_resize` calls `Win:update`. With the Claude window open, a resize of the editor runs `FileType claudecode` again, and a window option set in that handler then reaches the Claude window. Snacks also applies `bo` again when it re-creates a window itself. `snacks` lets it do that when `snacks_win_opts.position` is set to a value other than `left`, `right`, `top`, or `bottom` (for example `float`), and for a float that `snacks` hid whose window is gone. On Neovim before 0.10, hiding a float closes its window. A split is re-created with `split` (top or bottom) or `vsplit` (left or right), so `FileType` does not fire again for it [terminal/snacks.lua:build_opts] [terminal/snacks.lua:cc_show] [terminal/snacks.lua:cc_hide]
- `native` and `snacks` map terminal-mode `<C-z>` on the Claude terminal buffer to `<Cmd>suspend<CR>` through `utils.map_terminal_suspend`, once per terminal, and on no other buffer. A failed start maps none, and a hide or show of the same buffer maps none again. The mapping is buffer-local, so it shadows a global terminal-mode `<C-z>` mapping in that buffer. A buffer-local terminal-mode `<C-z>` mapping that already exists stays [utils.lua:M.map_terminal_suspend]
- `native` maps `<C-z>` right before it sets the filetype, so a `FileType claudecode` autocmd finds the mapping and can replace or delete it [terminal/native.lua:open_terminal]. `snacks` maps it after `Snacks.terminal.open` returns, which is after Snacks fired `FileType`, ran `on_buf`, and mapped its own keys. A handler can replace the mapping there, but a `vim.keymap.del` in a `FileType` handler finds nothing to delete [terminal/snacks.lua:M.open]
- `external` and `none` create no Neovim buffer, so they set no filetype [terminal/external.lua:M.open] [terminal/none.lua:M.open]
- `snacks` overrides the instance's `hide`, `show`, and `toggle` methods and keeps the originals in `term._cc`. The patched `show` always focuses, and the patched `toggle` focuses only when it shows the terminal (it hides a visible one and focuses nothing). Both use the config in `term._cc.config`: the config of the `open` that started the terminal, or for an adopted terminal the config of the last entry that passed one [terminal/snacks.lua:patch_instance] [terminal/snacks.lua:adopt_existing_terminal]
- `snacks` hides floats with `nvim_win_set_config({hide=true})` only on Neovim 0.10 and later. It also hides the Snacks backdrop window, and show un-hides both. When the cursor is in the float it hides, it runs `wincmd p` to leave it. It closes split windows and re-creates them on show. It closes a split through `pcall`, so hiding the last window does nothing [terminal/snacks.lua:cc_hide] [terminal/snacks.lua:set_backdrop_hidden]
- A top or bottom split that `snacks` re-creates takes its height from `snacks_win_opts.height`, else 30% of the editor lines. A left or right split takes its width from `snacks_win_opts.width`, else `split_width_percentage` of the editor columns, and gets the full editor height [terminal/snacks.lua:cc_show] [terminal/snacks.lua:resolve_split_size]
- `paste_fix` decides at phase 1 whether a streamed paste targets the managed terminal. It replays the whole paste once as phase -1, inside the captured window if focus moved. When that window is no longer valid, it replays in the current window [terminal/paste_fix.lua:M.install]
- `paste_fix` passes other pastes, and all pastes while disabled, to the original `vim.paste` unchanged. `is_managed_terminal` reads `vim.bo[bufnr].buftype` outside `pcall`, so it throws for an invalid `bufnr`. Its only caller passes the current buffer [terminal/paste_fix.lua:is_managed_terminal]
- The dispatcher's `setup` accepts a `provider` that is a table or one of `auto`, `snacks`, `native`, `external`, and `none`. It rejects any other value with a WARN notification, `Invalid value for provider: <value>. Keeping <provider>.`, and keeps the provider it had. That is `auto` until a valid value is set, and `auto` uses `snacks` when Snacks is available, else `native`. `get_provider` falls back to `native` with a warning for a stored value that `setup` would have rejected, which only a write to `terminal.defaults.provider` can leave [terminal.lua:M.setup] [terminal.lua:get_provider]

## Side Effects

- `native` runs `vsplit`, shows a new listed buffer from `nvim_create_buf` in the split, then runs `vim.fn.termopen` in that buffer with the command, env, and cwd. This spawns the Claude process. `native` shows its new terminal buffer, and a hidden one, in the split with `utils.win_set_buf_in_split`, as `snacks` does for a split that it re-creates and the diff does for the terminal in a new tab. A plain `nvim_win_set_buf` runs the `BufLeave` autocmds of the buffer it replaces inside the call, and when one of them enters another window, Neovim loads the terminal into that window, even though the call names the split. The helper fires that `BufLeave` itself, with `:doautocmd <nomodeline> BufLeave`, in the split, while the old buffer still shows there, so an autosave autocmd of the user's runs before the swap. When an autocmd moved the cursor, the helper puts it back in the split under `:noautocmd`, with no event. Then it makes the swap with `buffer!`, with `BufLeave` and `OptionSet` added to `'eventignore'`: `BufLeave` because it ran already, and `OptionSet` so that setting the option is silent. `:noautocmd` sets the caller's `'eventignore'` again afterwards, also when the swap fails, and fires no `OptionSet`. Neovim fires every other event of the swap itself, after the `BufLeave` autocmds are done and with the locks it holds then: `BufWinLeave`, `BufHidden` and `BufUnload` for a buffer that lost its last window, also when a `BufLeave` autocmd closed the other window of it, then `BufEnter` and `BufWinEnter`. The events and their order are a plain swap's, and `BufLeave` runs in the split, as in a plain swap. These differences remain. No `OptionSet` autocmd runs while the swap runs, also for an option that a `BufEnter` or `BufWinEnter` autocmd of the user's sets. A change of `'eventignore'` that an autocmd makes while the swap runs is undone afterwards. `'eventignore'` holds `BufLeave` for the whole swap and cannot name the old buffer, so a `++nested` `BufEnter` or `BufWinEnter` autocmd that leaves a buffer during the swap gets no `BufLeave`. When a `BufLeave` autocmd closes the split, the helper shows nothing and returns false, and the terminal stays hidden, where a plain swap loads it into the window that the cursor ends in. The buffer that the split shows after the `BufLeave` autocmds can be one that a plain swap leaves loaded and hidden: any buffer X that an autocmd showed there (a terminal with a running job, a scratch buffer, a changed or an unchanged file). `buffer!` unloads or wipes X when 'hidden' is off or its 'bufhidden' is `unload`, `delete` or `wipe`: a changed buffer loses its text, a terminal its job, a scratch buffer its text, a file its undo history and marks. The old buffer is the other case: when an autocmd closed its other window and it is changed, a plain swap, which decided before the autocmd ran, unloads or wipes it with its text when its 'bufhidden' says so, and the helper keeps it. So the helper sets the 'bufhidden' of that buffer to `hide` for the swap, with `:noautocmd` so that no `OptionSet` autocmd runs, and sets the old value again after the swap, also when the swap raises. The swap then fires `BufWinLeave` and `BufHidden` for X, which a plain swap does not fire for it (it fires them for the user's file, which still shows in another window), and a `BufHidden` autocmd of X sees `hide` while the swap runs. Those events run the user's own autocmds of X: an autosave on them writes X, a handler that raises makes the placement raise, and one that wipes X wipes it. A show of a hidden terminal without focus puts the cursor back in the window it was in, when that window still exists (the autocmd can have closed it too). Neither provider logs anything for a closed split, and `:ClaudeCode` and `:ClaudeCodeFocus` raise no error then. A diff in a new tab opens with no terminal when the autocmd closed the split, and enters the new tab again when the autocmd left it. When an autocmd wipes the terminal buffer, no window closed, and the helper shows nothing and returns false, as a plain swap shows nothing. `native` and `snacks` read the terminal's buffer number into a local before the split and the swap, because a user autocmd of the split or of the swap can close Claude, which clears the provider's record of the buffer. When a `BufEnter` or `TermOpen` autocmd closes the split (a `focus_toggle` from such an autocmd hides the half-started terminal), `native` goes on and tracks Claude as a hidden terminal with no window, and a later toggle shows it. The buffer is `bufhidden=hide` from the start, so closing the split never unloads it, also with `'nohidden'`, and the start sets it again when its autocmds are done, in case one changed it. When a later autocmd of the start showed it again in another window, `native` tracks that window, and the start focuses it only when it was asked to focus (an open that does not focus leaves you where you were). `native` runs the `vsplit` with all of your autocmds, so `WinLeave` of the window you leave (an autosave on `WinLeave` saves the file before Claude starts), `WinNew` and `WinEnter` run as for any split. One start runs at a time. An entry that an autocmd of the start calls before Claude has a buffer with a mark does nothing, because that start makes the one Claude: `open`, `simple_toggle` and `focus_toggle` from a `WinLeave`, `WinNew` or `WinEnter` autocmd of the split, or from a `BufNew` or `BufAdd` autocmd of the new buffer. A `close` that an autocmd of the start calls runs when the start returns, because a close waits for the job to exit and that wait cannot run inside `termopen`. It runs `startinsert` when focused and `auto_insert` is not `false` [terminal/native.lua:open_terminal, start_terminal]
- `native` on exit clears its state, for its own terminal and for an adopted one. With `auto_close` it closes the tracked window only if the window still shows the terminal buffer. When the buffer is gone (wiped), it closes no window. It never closes the last window (the only non-floating window of the only tab page), which keeps showing the exited terminal [terminal/native.lua:forget_exited_job]
- `native.close` clears its state and the buffer's mark, so an `open` that runs during the wait starts a new terminal. It registers a one-shot, buffer-local `TermClose` autocmd that detects the exit. Before it calls `jobstop`, a close of a job that started less than 10 s ago waits up to 1 s until the child of the job has run `exec` (the child has the name of its command then, not the name of Neovim). A job that was just started is still a fork of Neovim until then, and a `jobstop` on it ended Neovim with `SIGHUP` or left it hanging in the buffer delete. That happened in about 0.5 runs in 100 at a load average of 50, and in about 5 at a load average of 105, in a close that an autocmd of the start asked for and in an `open` followed by a `close` in one call. The names come from `/proc/<pid>/comm` on Linux, a read of a few bytes. Where `/proc` is missing (macOS, the BSDs), `nvim_get_proc` gives them, which runs `ps` (about 100 ms a call), so an older job skips the wait. When no name can be read (`ps` is missing), the close goes on to `jobstop`. The wait is `owned.wait_for_exec` [terminal/owned.lua:wait_for_exec], which `snacks.close` and the stop in `owned.lua` call too. A job that already exited has no pid, so the wait does not run. It calls `jobstop`, and when `jobstop` reports a running job, it waits up to 1 s for the job to exit. A close from a `TermClose` autocmd does not wait, because the job already exited. It then force-deletes the terminal buffer. Neovim closes the other windows that show it, and the editor's last window stays and shows another buffer. This works for a visible, hidden, or adopted terminal. Deleting the buffer before the job exits can hang Neovim when text sent to the job is still pending (neovim/neovim#42508). The wait does not prevent that hang for a job that stopped reading, for example `yes`, or `cat` after a large multi-line paste [terminal/native.lua:close_terminal]
- `snacks` calls `Snacks.terminal.open`, which spawns the Claude process [terminal/snacks.lua:M.open]
- `snacks` always registers a buffer-local `BufWipeout` handler. It registers a buffer-local `TermClose` handler only when `auto_close` is true. `TermClose` runs `checktime` and logs an ERROR on a nonzero exit, except when `close` stopped the job or the `native` provider stopped it directly (the stop clears the mark first). Both handlers stop tracking the instance only while it is still the tracked one [terminal/snacks.lua:setup_terminal_events]
- `snacks.close` stops tracking the instance first, so an `open` that runs during the wait starts a new terminal. For a running job, it registers a one-shot, buffer-local `TermClose` autocmd that
  detects the exit. A job that started less than 10 s ago first gets the exec wait of `native.close` (`owned.wait_for_exec`), because a `jobstop` on a child that has not run `exec` can end Neovim with `SIGHUP`. The start time sits in `term._cc.job_started_at`, so a terminal that a reload adopted has none and is not waited for. It stops the job and waits up to 1 s for it to exit. It then closes the Snacks window, which wipes the terminal buffer. Deleting the buffer before the job exits can hang Neovim
  when text sent to the job is still pending (neovim/neovim#42508). The wait does not prevent that hang for a job that stopped reading, for example `yes`, or `cat` after a large multi-line paste. An
  exited job is not waited for. With `auto_close`, a tracked terminal whose job already exited is forgotten before `close` looks at it, so `close` finds nothing to stop. Hide keeps the job running
  [terminal/snacks.lua:M.close]
- `native` and `snacks` call `vim.keymap.set` once for the Claude terminal buffer, in terminal mode, for `<C-z>` [utils.lua:M.map_terminal_suspend]. `:suspend` stops the Neovim TUI process, and a shell resumes it with `fg`
- `snacks` maps terminal-mode `<S-CR>` to send a backslash and then a carriage return after 10 ms [terminal/snacks.lua:build_opts]
- `snacks` sets window options and `vim.w[win].snacks_win` on re-created splits [terminal/snacks.lua:reapply_snacks_window_state]
- `external` spawns a detached process with `vim.fn.jobstart`. `close` calls `vim.fn.jobstop` [terminal/external.lua:M.close]
- `none` has no side effects [terminal/none.lua:M.open]
- `paste_fix.install` replaces the global `vim.paste` once. The dispatcher calls the provider's `setup(defaults)`, then `paste_fix.apply(defaults.fix_streamed_paste)`. The default is `"auto"`, and a value other than a boolean or `"auto"` gets a WARN and keeps the previous value [terminal.lua:M.setup]
