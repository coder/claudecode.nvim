# scripts

## Overview

`scripts/` holds developer and release tooling for claudecode.nvim. Nothing here is loaded by the plugin at runtime. The directory has three groups:

1. Test harnesses (`run_integration_tests_individually.sh`, `manual_test_helper.lua`).
2. Standalone reproductions of GitHub issues (`repro_issue_*.lua`, `repro_issue_*.sh`). `repro_issue_70_probe.lua` matches that pattern, but it is a helper that `repro_issue_70.sh` runs.
3. Release tooling: a release-please wrapper that writes changelog entries with Communique (`release-please-runner.js`, `run-release-please.sh`, `package.json`, `package-lock.json`). `test-release-please-runner.js` holds the tests for `release-please-runner.js`. It also runs the pinned `communique` binary with the repo's `communique.toml` against a fake Anthropic API, to check that one release-notes submission fits the configured output budget.

CI runs four of these files: `.github/workflows/release-please.yaml` runs `./scripts/run-release-please.sh`, and `.github/workflows/test.yml` runs `./scripts/run_integration_tests_individually.sh` and `nvim --headless -u NONE -c "luafile scripts/repro_issue_238.lua" -c "cquit 2"` on Neovim stable and v0.8.0, and `npm --prefix scripts run test:release-please-runner` (which runs `test-release-please-runner.js`).

`mise.toml` provisions `websocat` for `repro_issue_238.sh`, `repro_issue_248.sh`, and `repro_issue_277.sh`, `jq` for the repro scripts that parse JSON, and `communique` for the release tooling. It does not provide `agent-tty`, which `repro_issue_70.sh`, `repro_issue_218.sh`, and `repro_issue_277.sh` need. `repro_issue_277.sh` also needs `git` and `perl`, and `repro_issue_70.sh` needs a logged-in `claude` CLI [repro_issue_70.sh:MISSING dependency] [repro_issue_218.sh:agent-tty] [repro_issue_277.sh:MISSING dependency].

For a manual WebSocket check, use `.agents/skills/verify-claudecode-nvim/scripts/ws-client.mjs`: `node ws-client.mjs <lock file> <out file> <in file>` connects with the lock file's token, which it reads from the file so the token never appears in argv, sends each line you append to the out file, and appends each message it receives to the in file [.agents/skills/verify-claudecode-nvim/scripts/ws-client.mjs:authToken].

## Interface

### Test harnesses

- `run_integration_tests_individually.sh` (no arguments) runs each `tests/integration/*_spec.lua` in its own headless Neovim under `timeout 30s`, skips `command_args_spec.lua`, and prints totals [run_integration_tests_individually.sh:run_test_file].
- `manual_test_helper.lua` is run with `:luafile` in a Neovim that has the plugin on its `runtimepath`. It calls the `claudecode.tools.open_diff` handler in a coroutine and reports whether it yields [manual_test_helper.lua:test_opendiff_directly].

### Issue reproductions

The Lua repros run from the repository root with `nvim --headless -u NONE -l scripts/<file>`, which needs Neovim 0.9 or later. They prepend the repo root to `runtimepath` [repro_issue_208.lua:rtp:prepend]. `repro_issue_70_probe.lua` is the exception: it prepends `<repo_root>/lua` to `package.path` instead [repro_issue_70_probe.lua:package.path]. `repro_issue_238.lua` runs with the `:luafile` command in its entry below, which also works on Neovim 0.8.

- `repro_issue_70.sh` (#70) checks whether the `claude` CLI connects back to the plugin when an HTTP proxy has no localhost exclusion. It prints `PASS issue #70 reproduced` (exit 0) or `INCONCLUSIVE` (exit 1). It drives `repro_issue_70_probe.lua` [repro_issue_70.sh:run_scenario]. It needs `nvim`, `claude`, `agent-tty`, and `jq`, and exits 3 when one is missing [repro_issue_70.sh:MISSING dependency].
- `repro_issue_70_probe.lua <repo_root> <status_file> <stop_file> [wait_ms]` is a helper, not a standalone repro. `wait_ms` defaults to 120000 [repro_issue_70_probe.lua:wait_ms]. It starts the real server with `terminal.provider = "none"` and writes `phase`/`connected` JSON to the status file. Exit 0 means a connection was seen, 2 means none, and 1 means no port [repro_issue_70_probe.lua:write_status].
- `repro_issue_208.lua` (#208) checks for a leftover `[No Name]` tab or buffer after a diff resolves with `open_in_new_tab=true` and `provider=none`. Exit 0 means fixed, 1 means reproduced [repro_issue_208.lua:verdict].
- `repro_issue_218.sh [--no-render-markdown]` (#218) checks for a Neovim crash when a new-file markdown diff is accepted in a new tab with render-markdown.nvim. `NVIM_BIN` selects the binary. Exit 0 means the expected outcome happened. Exit 1 also covers a missing `agent-tty` or `nvim` and a failed `agent-tty` session. It uses `jq` but does not check for it [repro_issue_218.sh:WANT_RM, NVIM_BIN, SID].
- `repro_issue_231.lua` (#231) checks that a terminal-only layout does not fail with "No suitable editor window found". Exit 0 means fixed, 1 means reproduced [repro_issue_231.lua:verdict].
- `repro_issue_232.lua` (#232) checks for a `BufEnter` auto-insert autocmd on the terminal buffer. Env: `CLAUDECODE_PROVIDER=snacks|native`, `CLAUDECODE_AUTO_INSERT=true|false`. Exit 1 means reproduced, 0 means not reproduced or skipped, and 2 means a setup error [repro_issue_232.lua:reproduced]. `CLAUDECODE_PROVIDER` defaults to `snacks`. The script looks for snacks.nvim only at `~/.local/share/nvim/lazy/snacks.nvim` and `~/.local/share/*/lazy/snacks.nvim`, and prints `SKIP` (exit 0) when it cannot load it [repro_issue_232.lua:provider, candidates].
- `repro_issue_238.lua` (#238) checks that `:q` on the proposed window rejects the diff. CI runs it with `nvim --headless -u NONE -c "luafile scripts/repro_issue_238.lua" -c "cquit 2"`, which also works on Neovim 0.8. Exit 0 means fixed, 1 means reproduced, and 2 means the script raised an error before its verdict [repro_issue_238.lua:verdict]. It runs `open_in_new_tab=false`, `open_in_new_tab=true`, a split proposed window, and a new file. It finds the repo root with `:h:h` on its own path. `luafile` passes that path as you typed it, so run the CI command from the repo root, or pass an absolute path. Run from `scripts/` with a bare file name, it cannot load `claudecode.diff` and exits 2 [repro_issue_238.lua:run_scenario, run_multiwindow_scenario, run_newfile_scenario, repo_root].
- `repro_issue_238.sh --file PATH [--lock-dir DIR] [--out FILE] [--hold SEC] [--tab NAME]` (#238) is an external MCP client. It opens one `openDiff` and holds the socket while you run `:q` in Neovim. It prints a `RESULT:` line, but its exit code does not reflect the result [repro_issue_238.sh:RESULT]. `-h` prints the usage header. The lock directory is `CLAUDE_LOCKFILE_DIR`, else `$CLAUDE_CONFIG_DIR/ide`, else `$HOME/.claude/ide`, and `WEBSOCAT` overrides the binary. Exit 2 means a bad or missing argument, and exit 1 means a missing tool, lock file, or token. The proposed contents replace the text `line three` in `--file`, so a file without that text gets a diff with no change [repro_issue_238.sh:LOCK_DIR, WEBSOCAT, contents].
- `repro_issue_246.lua` (#246) checks that single-line and fast visual selections reach Claude. Exit 0 means all checks pass, 1 means a check failed [repro_issue_246.lua:check].
- `repro_issue_248.sh [-n|--num N] [--cleanup]` (#248) opens N diffs and disconnects without `close_tab`. It prints no verdict: run `:DiffState` in Neovim and read the counts [repro_issue_248.sh:NUM_DIFFS, CLEANUP]. `:DiffState` comes from the `fixtures/remote-diff` config. N is a cap: the script diffs the first N sorted `*.txt`, `*.lua`, and `*.md` files at the top level of `workspaceFolders[0]`. `-h` or `--help` prints the usage header, and an unknown argument exits 2. It exits 1 for a missing tool, a missing lock file, token, or workspace, or no file to diff. It exits 0 otherwise, because it ignores a `websocat` failure. It uses `mapfile`, so it needs bash 4 or later [repro_issue_248.sh:LOCK_DIR, FILES].
- `repro_issue_262.lua` (#262) checks that a setup error after `:tabnew` does not strand a tab. Exit 0 means fixed, 1 means reproduced [repro_issue_262.lua:verdict].
- `repro_issue_277.sh` (#277) runs three phases. Phases 1 and 3 check whether `closeAllDiffTabs` also closes diffview.nvim and user vimdiff windows. Phase 2 checks whether `openFile` runs `:edit` into a foreign diff window. `ISSUE277_ARTIFACTS` sets the artifact directory. The exit code covers all three phases: exit 0 means all three phases reproduced, 1 means a phase was not reproduced, 2 means a setup failure, and 3 means a missing tool [repro_issue_277.sh:PASS, FAIL, WEBSOCAT]. When `websocat --version` fails, the script searches `${MISE_DATA_DIR:-$HOME/.local/share/mise}/installs/websocat` for a working `websocat` binary. It exits 3 when that search finds no working binary [repro_issue_277.sh:WEBSOCAT].
- `repro_issue_283.lua` (#283) checks the port probe. `REPRO283_MODE` selects `mechanism` (the default, also used for an unknown value), `port`, or `serve`. Serve mode reads `REPRO283_LABEL` and `REPRO283_WAIT_MS` (default 6000) [repro_issue_283.lua:mode, label, wait_ms]. Mechanism mode rebuilds the probe with raw `vim.loop` handles and calls no plugin code. Its exit 1 means libuv accepted a bind on a busy port and failed later at `listen`. That result does not change when the plugin is fixed [repro_issue_283.lua:reproduced].
- `repro_issue_283.sh` (#283) runs `repro_issue_283.lua` in all three modes. `NVIM` overrides the binary, and the script exits 2 when it cannot find it. Exit 1 means all three parts reproduced. Exit 0 means "not fully reproduced", not "pass" [repro_issue_283.sh:VERDICT]. Part 3 looks for the text `Failed to listen on port .*EADDRINUSE`. The current `create_server` moves on to the next port and never returns that text, so on current code the script exits 0 [repro_issue_283.sh:E2E] [lua/claudecode/server/tcp.lua:create_server].
- `repro_issue_285.lua` (#285) checks that a path with a `$post` segment is accepted by `:ClaudeCodeAdd` and the `openFile` handler, and that `:ClaudeCodeAdd %` still works. Exit 0 means fixed, 1 means reproduced or a regression [repro_issue_285.lua:verdict].
- `repro_issue_289.lua` (#289) checks that `ClaudeCodeSend` does not treat a Lua buffer as a file-tree buffer because its path contains `neo-tree`. It tests a `_neo-tree_.lua` path against a control path. It does not test an `NvimTree` path. Exit 1 means reproduced [repro_issue_289.lua:AFFECTED, affected_misrouted].

### Release tooling

- `run-release-please.sh [args]` changes to the repo root and runs `node release-please-runner.js`. It uses `scripts/node_modules/release-please` when present, else the `release-please` on `PATH` through `NODE_PATH`. When it finds neither, it exits 1 with no message [run-release-please.sh:release_please_bin].
- `node release-please-runner.js [--dry-run]` registers Communique-generated changelog notes and the `simple` release type, then creates releases and release PRs. Without `--dry-run` it prints `release-please: releases=[...] prs=[...]`. With `--dry-run` it prints JSON with `releases` and `pullRequests` (including `changelogPreview`) and writes nothing to GitHub. `--dry-run` still needs `GITHUB_TOKEN` and still reads from the GitHub API. Any error sets exit code 1 [release-please-runner.js:main].
- `buildCommuniqueArgs` builds `communique generate HEAD [PREVIOUS_TAG] --concise --repo OWNER/REPO --output <tmp>/notes.md [--model COMMUNIQUE_MODEL]` [release-please-runner.js:buildCommuniqueArgs].
- Environment for `release-please-runner.js`: `GITHUB_TOKEN` and `GITHUB_REPOSITORY` (required), `RELEASE_PLEASE_TARGET_BRANCH`, `GITHUB_OUTPUT`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `COMMUNIQUE_MODEL`, and `PRETTIER_BIN` [release-please-runner.js:requireEnv, assertLlmCredentials, resolvePrettierBin].
- `release-please-runner.js` exports `CommuniqueSimpleStrategy`, `UnreleasedAwareChangelog`, `assertLlmCredentials`, `buildCommuniqueArgs`, `createCommuniqueChangelogNotes`, `findLineOutsideFences`, `formatChangelogMarkdown`, `formatChangelogSection`, `formatPullRequestOutputs`, `formatReleaseOutputs`, `normalizeCommuniqueBody`, `resolvePrettierBin`, `releasePleaseNotesAreEmpty`, and `todayIsoDate` [release-please-runner.js:module.exports].
- GitHub Actions outputs: `releases_created`, `release_tags`, `prs_created`, `pr_branches`, and `pr_metadata` [release-please-runner.js:formatReleaseOutputs, formatPullRequestOutputs].
- `package.json` is the private package `claudecode.nvim-release-tools`. It pins `prettier` 3.8.4 and `release-please` 17.9.0 and defines the `test:release-please-runner` script [package.json:scripts]. `package-lock.json` locks the full dependency tree of `package.json` [package-lock.json:packages]. Both CI workflows install from it with `npm ci --prefix scripts` [.github/workflows/test.yml:npm ci] [.github/workflows/release-please.yaml:npm ci].
- `test-release-please-runner.js` takes no arguments and prints nothing on success. `npm run` prints only its own two-line header. It needs `git`, `prettier`, the `release-please` package, a real `communique` binary on `PATH` (for example under `mise exec --`), and the repo's `communique.toml`. It runs `communique` in a temp directory outside the repo. There a mise shim for the `communique` that the repo's `mise.toml` pins prints `communique is not a valid shim`, and the test exits 1. Its Communique check asserts that one release-notes submission is between 4096 and 8192 tokens and gets through in one request [test-release-please-runner.js:testCommuniqueConfigFitsReleaseNotes].

## Invariants

- `repro_issue_238.sh` and `repro_issue_248.sh` find the server port from the lock file name (`PORT.lock`) in a lock directory, and send the lock file's `authToken` in the `x-claude-code-ide-authorization` header. `repro_issue_277.sh` sends the same header, but reads the port and the token from the plugin state through nvim RPC [repro_issue_238.sh:TOKEN] [repro_issue_248.sh:TOKEN] [repro_issue_277.sh:TOKEN]. All three put the URL before `--header`, which websocat 1.14.1 accepts [repro_issue_238.sh:WEBSOCAT] [repro_issue_277.sh:WEBSOCAT].
- `run_integration_tests_individually.sh` must run from the repo root. It adds a file to `FAILED_FILES` when it parses failures or errors, or when nvim exits nonzero with a code other than 124 or 143 (timeouts). This includes an nvim crash that prints no `Failed :` line. A spec that times out without a parsed failure or error counts as passed. The script exits 1 when `FAILED_FILES` is non-empty, else 0 [run_integration_tests_individually.sh:FAILED_FILES, EXIT_CODE].
- `repro_issue_238.sh` and `repro_issue_248.sh` take the first lock file found, not the newest [repro_issue_238.sh:LOCK_FILE] [repro_issue_248.sh:LOCK_FILE].
- `repro_issue_238.sh` and `repro_issue_248.sh` read `CLAUDE_LOCKFILE_DIR` from the environment. `repro_issue_248.sh` falls back to `$HOME/.claude/ide` and ignores `CLAUDE_CONFIG_DIR` [repro_issue_238.sh:LOCK_DIR] [repro_issue_248.sh:LOCK_DIR].
- `manual_test_helper.lua` hardcodes an absolute path to `README.md` in one developer's checkout, and returns early when that file is not readable [manual_test_helper.lua:readme_path].
- `repro_issue_70_probe.lua` resolves the lock directory from `CLAUDE_CONFIG_DIR/ide`, else `$HOME/.claude/ide` [repro_issue_70_probe.lua:config_dir].
- The Lua repros call private plugin functions, for example `diff._setup_blocking_diff`, `diff._cleanup_all_active_diffs`, `selection._cancel_demotion_timer`, and `claudecode._create_commands`. A rename of one of these breaks the repro that calls it [repro_issue_208.lua:_setup_blocking_diff] [repro_issue_246.lua:_cancel_demotion_timer] [repro_issue_285.lua:_create_commands].
- Some Lua repros exit 0 ("fixed") when the run did not prove a fix. `repro_issue_208.lua` prints a setup error but does not count it as a leak. `repro_issue_231.lua` reports fixed when scenario A fails with any error other than "No suitable editor window found". A failed control scenario only prints a warning in `repro_issue_262.lua` and `repro_issue_285.lua`. In `repro_issue_289.lua` it forces exit 0 ("fixed"), even when the affected buffer was misrouted [repro_issue_208.lua:setup_ok] [repro_issue_231.lua:bug_reproduced] [repro_issue_262.lua:control] [repro_issue_285.lua:WARNING, regressed] [repro_issue_289.lua:control_ok].
- `release-please-runner.js` requires `GITHUB_TOKEN` and `GITHUB_REPOSITORY` in `owner/repo` form [release-please-runner.js:requireEnv, main].
- `assertLlmCredentials` throws when both `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` are empty, or when `ANTHROPIC_API_KEY` is empty and `COMMUNIQUE_MODEL` is unset [release-please-runner.js:assertLlmCredentials].
- When default release-please notes have one line or fewer, the runner returns them without calling Communique [release-please-runner.js:releasePleaseNotesAreEmpty].
- `UnreleasedAwareChangelog` keeps the first `## [Unreleased]` or `### [Unreleased]` heading and inserts the new entry below it. It drops the draft lines under that heading, up to the next `#` or `##` heading. When the heading is missing, it adds `## [Unreleased]` below the `# ` title. Headings inside code fences are ignored [release-please-runner.js:UnreleasedAwareChangelog, findLineOutsideFences, NEXT_SECTION_PATTERN].
- release-please reads its config and manifest from the remote target branch (`RELEASE_PLEASE_TARGET_BRANCH`, else the default branch), not from the local checkout. Local edits to `release-please-config.json` take effect only after you push them [release-please-runner.js:main].
- The runner imports internal modules from `release-please/build/src/`, so it depends on the file layout of the pinned `release-please` version [release-please-runner.js:Simple, Changelog].
- `formatChangelogSection` asserts a non-empty version and a `YYYY-MM-DD` date, and writes `## [VERSION] - DATE` without a `v` prefix [release-please-runner.js:formatChangelogSection].
- `resolvePrettierBin` uses `PRETTIER_BIN`, then `scripts/node_modules/.bin/prettier`, then `prettier` on `PATH` [release-please-runner.js:resolvePrettierBin].
- `main` creates releases before release PRs [release-please-runner.js:main].

## Side Effects

- CAUTION: Do not run the token-sending clients (`repro_issue_238.sh`, `repro_issue_248.sh`, and `repro_issue_277.sh`) on a shared machine. They pass the auth token on the `websocat` command line (`--header`), where other users can read it with `ps` [repro_issue_238.sh:WEBSOCAT] [repro_issue_248.sh:TOKEN] [repro_issue_277.sh:TOKEN].
- `repro_issue_238.sh`, `repro_issue_248.sh`, and `repro_issue_277.sh` connect to the plugin server on `127.0.0.1` [repro_issue_238.sh:PORT] [repro_issue_248.sh:PORT] [repro_issue_277.sh:PORT].
- `run_integration_tests_individually.sh` creates one `mktemp` file per test and deletes it [run_integration_tests_individually.sh:temp_output]. Each nvim it starts loads `tests/minimal_init.lua`, which runs `git clone` of plenary.nvim into `stdpath("data")` when plenary is missing [run_integration_tests_individually.sh:run_test_file].
- The Lua repros create temp files or directories, stub plugin functions (for example `logger`, `vim.notify`, `diff._create_diff_view_from_window`), and rearrange tabs and windows inside their own headless Neovim [repro_issue_285.lua:logger] [repro_issue_289.lua:vim.notify] [repro_issue_262.lua:_create_diff_view_from_window].
- `repro_issue_231.lua` deletes `<repo_root>/__issue_231_repro__.md` [repro_issue_231.lua:try_open_diff].
- `repro_issue_70.sh` and `repro_issue_277.sh` create `agent-tty` sessions and temp directories, and remove both on exit. They create the temp directory before they install the `EXIT` trap, so an exit 3 for a missing tool leaves that directory behind. `repro_issue_70.sh` launches the real `claude` CLI and sets proxy variables to `http://127.0.0.1:1` in its scenarios [repro_issue_70.sh:run_scenario] [repro_issue_277.sh:cleanup]. Its cleanup runs `pkill -f "repro_issue_70_probe.lua $REPO_ROOT"`, which also kills the probe of another run in the same checkout [repro_issue_70.sh:cleanup].
- `repro_issue_70_probe.lua` starts the real server with `auto_start = true`, so the plugin writes a real `PORT.lock` into the user's lock directory. Other Claude CLIs can see that lock file until `claudecode.stop()` removes it at the end [repro_issue_70_probe.lua:claudecode.setup, claudecode.stop].
- `repro_issue_277.sh` clones diffview.nvim into `${XDG_DATA_HOME:-$HOME/.local/share}/issue-277/diffview.nvim` when it is absent. It copies artifacts to `${TMPDIR:-/tmp}/issue277-artifacts-latest` when `ISSUE277_ARTIFACTS` is unset [repro_issue_277.sh:DIFFVIEW_DIR].
- `repro_issue_218.sh` runs `Lazy! sync`, which downloads fixture plugins. The fixture clones lazy.nvim and the plugins into `stdpath("data")/lazy` of `NVIM_APPNAME` `issue-218`, or `issue-218norm` with `--no-render-markdown`, outside the temp directory. The default run sets `XDG_CONFIG_HOME` to the repo's `fixtures/` directory, so `Lazy! sync` also rewrites the tracked file `fixtures/issue-218/lazy-lock.json`. The `--no-render-markdown` run writes its lock file in the temp directory. The script does not remove its temp directory [repro_issue_218.sh:APPNAME, CONFHOME, cleanup].
- When `--out` is omitted, `repro_issue_238.sh` writes the frames to a `mktemp` file `repro238.frames.*` and does not delete it. Its `EXIT` trap removes only the request file [repro_issue_238.sh:OUT, REQ].
- Without `--cleanup`, `repro_issue_248.sh` disconnects without `close_tab`. The server then rejects and closes that client's pending diffs, so `:DiffState` shows `active_diffs=0`. With `--cleanup` it calls `closeAllDiffTabs` first [repro_issue_248.sh:CLEANUP].
- `repro_issue_283.lua` binds TCP sockets on `127.0.0.1`. `repro_issue_283.sh` starts a background Neovim and kills it on exit [repro_issue_283.lua:listener:bind] [repro_issue_283.sh:cleanup].
- `release-please-runner.js` without `--dry-run` creates GitHub tags, releases, and pull requests through the GitHub API [release-please-runner.js:main].
- `release-please-runner.js` spawns `communique generate` with the full environment (API keys included) in the current directory, which is the repo root when `run-release-please.sh` starts it. Communique writes `notes.md` to a temp directory `communique-notes-*`, which the runner removes afterward. It runs `prettier` on each changelog update and appends outputs to `GITHUB_OUTPUT`, or prints them when that variable is unset [release-please-runner.js:createCommuniqueChangelogNotes, formatChangelogMarkdown, writeGithubOutputs].
- `test-release-please-runner.js` starts an HTTP server on a random `127.0.0.1` port and runs `git` and `communique` in a temp directory `communique-config-*` that it removes afterward. It passes `communique` only a placeholder API key [test-release-please-runner.js:testCommuniqueConfigFitsReleaseNotes].

## Verification

- Run: `mise exec -- npm --prefix scripts run test:release-please-runner` (needs `npm --prefix scripts ci` first). `mise exec --` puts the real `communique` binary that `mise install` provides on `PATH`. The mise shim fails, as `test-release-please-runner.js` above describes.
- Run: `mise run format-check`. treefmt formats and lints `scripts/` with `shfmt` and `shellcheck` (`*.sh`), `stylua` (`*.lua`), and `prettier` (`*.js`, `*.json`, `*.md`).
- `mise run check` runs `luacheck` on `lua/` and `tests/` only, so it does not cover `scripts/`.
